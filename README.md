# Experiment Annotator

A simple Windows application for manually annotating experiment stages during a recording session.

No installation is required.

## Quick Start

Double-click:

`Start-Annotator.bat`

Then:

1. Choose the **Protocol** (stage list) in the top bar, or click **Load file...** to use another one.
2. Enter the **Participant ID** and **Session ID**.
3. Click **Start Session**.
4. Press the large annotation button at the start and end of each experiment stage.
5. Check the event log after each click to confirm that the annotation was recorded.
6. At the end of the experiment, review the session summary and stage durations.
7. Click **New Session** to run the next session without restarting (the session ID is incremented automatically).

If you make a mistake, use **Correct last annotation**.

Corrections are recorded explicitly in the log. Previous data is never deleted.

## Output Files

Session data is stored automatically in the `annotations/` folder next to the application.

For example:

```text
annotations/
├── P001_S01_annotations.csv
└── P001_S01_annotations.json
```

If files with the same participant and session IDs already exist, the application automatically creates a new run:

```text
P001_S01_annotations_run2.csv
P001_S01_annotations_run2.json
```

Existing files are never overwritten.

At the end of the session, click **Open data folder** to open the output directory.

## Session Workflow

A typical session follows this sequence:

```text
Start Session
    ↓
Stage 1 Start
    ↓
Stage 1 Finish
    ↓
Stage 2 Start
    ↓
Stage 2 Finish
    ↓
...
    ↓
Session Complete
```

The final summary checks whether every stage contains the expected annotations and reports the recorded durations.

## Correcting an Annotation

If you accidentally press the annotation button at the wrong time, click:

**Correct last annotation**

This does not delete or modify previous log entries.

Instead, a new `CORRECTION` event is added. The correction invalidates the most recent valid event, rolls the protocol state back, and allows that stage annotation to be recorded again.

This keeps the annotation history fully traceable.

## Changing the Experiment Protocol

The experiment stages are defined in protocol files, not in the code.

Put `.json` or `.txt` files in the `protocols/` folder and they appear in the **Protocol** dropdown. Any file can also be loaded with **Load file...**. The protocol cannot be changed while a session is running.

JSON example:

```json
{
  "name": "My experiment",
  "stages": ["Baseline", "Task 1", "Task 2", "Recovery"]
}
```

A bare list (`["A", "B"]`) and stages written as `{"name": "..."}` also work. A `.txt` file has one stage per line; lines starting with `#` are ignored.

Rules: stage names must be unique, non-empty and at most 60 characters, with 1-40 stages. Invalid files are rejected with a message and the current protocol stays active.

To start with a specific protocol (for example one generated by another program):

```text
Start-Annotator.bat path\to\protocol.json
powershell -STA -File Start-Annotator.ps1 -ProtocolSource '{"name":"x","stages":["A","B"]}'
```

You can also drag a protocol file onto `Start-Annotator.bat`. The protocol name, source and stage list are saved in the JSON output.

## Components

| File | Role |
|---|---|
| `Clock.ps1` | Provides the OS wall clock and a monotonic clock for accurate duration measurements |
| `Protocol.ps1` | Loads and validates protocols and manages the session state machine and corrections |
| `Validation.ps1` | Checks stage completeness and consistency and generates the final report |
| `Logger.ps1` | Appends events to CSV and writes an atomic JSON snapshot; data is flushed to disk after every event |
| `Gui.ps1` | Implements the Windows Forms user interface |
| `Start-Annotator.bat` | Starts the annotation application |

## Timing

The first event of every session is:

```text
SESSION_START
```

Its elapsed time is:

```text
0.000
```

All subsequent elapsed times are calculated using a monotonic clock relative to `SESSION_START`.

The system therefore keeps two notions of time:

- **Wall-clock time** for the actual timestamp of an event.
- **Monotonic elapsed time** for reliable duration measurements.

Using a monotonic clock avoids duration errors caused by changes to the system clock.

## Session Events

Some important event types are:

```text
SESSION_START
CORRECTION
SESSION_END
SESSION_RESET
```

A `CORRECTION` invalidates the most recent valid annotation and restores the previous protocol state.

`SESSION_END` and `SESSION_RESET` indicate that a session was closed before completing the full protocol.

## Data Safety

The application is designed to minimize data loss during experiments.

After every annotation:

- the CSV file is updated,
- the JSON snapshot is updated,
- the data is flushed to disk.

If the application or computer crashes during a session, the recorded files remain intact up to the last successfully registered click.

However, interrupted sessions currently **cannot be resumed**. A new session must be started.
